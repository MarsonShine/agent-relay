# M1 控制内核契约

M1 只运行无模型费用、只读的 simulation 任务。实体和执行输入/输出均带 `schemaVersion: 1`；数据库迁移版本与协议版本分别管理。M0 尚未验证的真实写入能力保持禁用。

配置使用严格 schema。角色 design / implement / review 与执行器、供应商、模型、权限分别记录，配置在创建任务时冻结，运行再次保存快照。当前唯一允许的组合为 fake / simulation / simulator-v1 / read-only；原生参数由 fake 适配器定义。未知字段、未知模型、未支持权限和无限预算均拒绝。

需求版本和代码版本绑定每个 Run、Artifact、Finding。代码版本可以为空，表示没有代码验证证据；不得把空版本解释为任意提交。resolved 发现必须有复验说明。金额和 token 用量不可见时记为未知。

执行接口由 start、continue、cancel、reconcile 和事件流/结果组成。续接引用是不透明字符串；工作流不能解析原生会话 ID。能力不支持时显式失败，不自动换模型或放宽权限。M1 定义 Finding 的持久格式，审查与发现处理工作流在 M2 实现。

SQLite 在启动时以事务执行有序 migration，拒绝较新数据库版本，并执行 quick_check。创建任务的 requestKey 绑定规范化后的完整请求；同键同内容返回原任务，同键不同内容报冲突。任务命令带 expectedVersion；旧版本、终态修改、未确认停止时 resume 均拒绝。状态、事件和 Decision 同事务保存。事件序号全局单调，按任务分页读取；相同事件键内容不一致报冲突。

answer 必须匹配 waiting_user 的问题 ID/版本，保存 Decision 并增加 requirementVersion；旧成果仍可查看但不能作为新需求的完成证据。暂停保留 deadline 和已消耗预算；暂停待答复任务后恢复仍回到 waiting_user。

运行领取、消耗次数、配置快照、租约及领取事件在同一事务持久化。数据库部分唯一索引限制全局最多一个 active/unknown Run，符合 v1 默认串行执行。租约由随机 owner 标识约束；过期续租及旧 owner 结果拒绝。过期只进入 recovering，不回收占位。执行器明确确认停止后才释放；未知状态不会启动第二个运行。

pause/cancel 活动运行时先持久化控制意图并进入 recovering。停止确认之前不能 resume；完成与取消竞态按事务顺序决定，已保存的 cancel 优先于迟到成功。M1 重启后无法核对的模拟进程保留 recovering；生产进程身份与副作用恢复由 M3 完善，不根据 PID 或到期时间猜测停止。
