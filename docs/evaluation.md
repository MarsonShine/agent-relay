# 验证与评测

## 系统正确性

用可控模拟执行器和进程样本验证状态机与生命周期：JSONL 半行和未知事件、非零退出、缺少终态、重复事件、取消竞态、孤儿进程、预算耗尽、数据库迁移和外部副作用恢复。

测试必须证明系统契约。例如 PR 已创建但本地记录失败时，恢复应识别现有 PR，而不是再次创建。测试不以复制实现分支或固定数量为目标。

真实 Codex 验证覆盖读取、修改、工具运行、会话续接、权限、取消及输出协议。记录 CLI、操作系统、配置和模型信息；模拟通过不能代替真实接入通过。

## 任务质量

试点选择有明确验收的小范围缺陷、功能、咨询任务，包括至少一种容易出现目标歧义或设计退回的情况。使用现有项目检查，并为确有风险的回归缺口补充验证。

验收基线应在执行前确定，评估期间不得由工作 Agent 自行放宽。评测任务可以允许 Agent 修改项目测试，但评估者另行维护可信验收依据。

## 比较设计

- 基线 1：单 Agent 执行与自检。
- 基线 2：同模型独立角色与审查反馈。
- 基线 3：异模型角色与审查反馈（API runtime 可用后）。
- 控制任务、基线代码、可用工具、验收与预算；重复执行以观察随机性。
- 同时改变模型和 harness 时，标记为系统配置比较。
- 小样本结果报告原始计数与局限，不声称普遍最优。

## 指标

任务验收通过率、有效发现与漏检、人工介入原因、反馈轮次、完成时间、重试次数、token/费用可见性、合并后返工。不能以 Agent 自评分或彼此一致作为主要成功指标。

记录观测到的请求配置和版本；未暴露的实际模型版本或计费记为未知。只有运行时能提供中途用量时才承诺对应粒度的预算执行；其余使用运行次数、时限与供应商账户限额配合。

## 证据留存

每次结果关联任务/需求版本、输入提交、成果提交、Agent 配置、运行时版本和验证环境。保存脱敏可复现实验说明，原始任务代码与凭据不上传公开仓库。
