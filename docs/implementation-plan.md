# 具体实现计划

M1.1–M1.7 已实现，本机检查及 Windows/Linux CI 均通过。详见 [M1 契约与验收](m1.md)。M0 的真实修改、续接和活动工具取消已复验通过，但只读隔离失败，见 [M0 结果](m0/README.md)；M1 只使用模拟后端，不依赖未经验证的自动写入能力。M2–M4 未开始，API Agent 不阻塞 v1。

## M0：Codex CLI 接入验证

目标：以最小实验消除执行后端不确定性。

- M0.1 记录 Node、Git、Codex 路径与版本、认证状态，确定可重复的开发环境。
- M0.2 在临时测试仓库执行只读调查，采集脱敏 JSONL，验证 stdin、工作目录和结构化结果。
- M0.3 执行有限文件修改与本地检查；保存会话 ID，指定该 ID 输入反馈并续接，核对同一工作区。
- M0.4 验证模型/思考配置、不支持参数错误、无认证和权限不足的表现。
- M0.5 验证取消、进程树、退出、缺失终态、静默与重启核对。涉及真实模型调用时明确运行预算。
- M0.6 写入兼容性矩阵：已测版本、命令、配置、结果、限制及脱敏事件样本。

验收：至少证明调查→修改→反馈续接的真实链路；取消后不会有继续写入的遗留进程。不可验证的能力显式禁用。当前本机 alpha 版本只是观察值，不直接成为支持版本承诺。

## M1：控制内核与执行契约（依赖 M0；内核模拟验收通过）

- [x] M1.1 初始化 TypeScript 项目，锁定工具链、格式/类型检查、Windows/Linux CI。
- [x] M1.2 定义 Task、Run、Event、Artifact、Finding、Decision 及执行接口、schemaVersion。
- [x] M1.3 SQLite migration、事务转移、版本检查、任务领取与租约。
- [x] M1.4 本地服务与 CLI：create/status/events/answer/pause/resume/cancel；明确本机认证边界。
- [x] M1.5 模拟执行器验证正常、失败、无终态、重复事件、取消竞态。
- [x] M1.6 配置校验：角色、模型、原生参数、权限、有限预算；拒绝未知配置。
- [x] M1.7 日志与成果存储、脱敏、大小限制及故障诊断。

验收：重复提交和服务重启不双重领取任务；非法状态转移被拒绝；模拟后端可在不改变工作流代码的情况下替换。上述项已在 Windows 本机及 Windows/Linux CI 通过，包含独立 OS 进程竞争、服务强制终止及重启。此阶段没有自研 API 工具循环；M0 的只读权限隔离失败仍单独阻塞 M2。

## M2：本地研发闭环（依赖 M1）

- M2.1 实现 Codex CLI 适配器，使用 M0 事件样本验证流解析和版本行为。
- M2.2 实现 worktree 管理、单写入者、基线提交和固定审查快照。
- M2.3 实现 triage/design/implement/review 交接及语义校验。
- M2.4 接入可信验证命令，保存退出码、日志、环境和 SHA。
- M2.5 实现有界审查→修复与设计退回；保存发现的处理证据。
- M2.6 使用 MS.Microservice 的小范围任务试点，复用项目现有规范和测试地图。

验收：真实任务经过一次有意义的反馈处理后产生可验证变更；咨询路径不制造无关分支；原工作区不被修改；失败检查不能被模型报告覆盖。

## M3：持续协作和可靠恢复（依赖 M2）

- M3.1 版本化用户问题、答复、需求变更与旧证据失效。
- M3.2 暂停/取消/恢复的运行核对与写租约回收。
- M3.3 分离基础设施重试和任务修复预算，增加总时限与无进展检测。
- M3.4 持久化待执行意图与启动恢复扫描。
- M3.5 注入崩溃：启动前后、修改后、结果落库前、取消与完成同时发生。

验收：服务重启不会创建第二位写入者；等待答复不消耗模型运行；预算不能因重启重置；恢复不重放未知副作用。

## M4：GitHub PR 交付（依赖 M3）

- M4.1 导入指定 issue，保存来源与版本；配置可信反馈者和交付权限。
- M4.2 推送专属分支并创建/更新 PR；写入幂等标识与交付记录。
- M4.3 有界轮询 CI/评论，保存 cursor，去重并忽略自身事件。
- M4.4 CI 失败分类、将有效反馈路由回实现/设计，重新检查当前 SHA。
- M4.5 核对外部成功但本地落库失败、PR 已存在、远端被用户修改、PR 被关闭等情形。
- M4.6 输出交付报告、已验证范围与剩余风险；整理真实使用说明。

验收：真实 issue→PR→反馈→更新链路成立；故障重跑不重复创建 PR；最终证据与当前提交一致。v1 到此交付，默认不合并。

## 每个开发切片的交付规则

1. 明确变更对应的契约与验收条件。
2. 实施最小可验证切片，修改相关文档。
3. 运行与风险匹配的验证；外部实测与模拟结果分开记录。
4. 记录已完成内容、证据和下一切片，不以固定测试数量替代覆盖判断。

## 依赖与暂未确定项

GitHub 身份验证、许可证、Codex 支持版本与默认超时在相应阶段解决。除用户凭据与必要业务决定外，常规实现选型在里程碑内依据验证结果确定。当前不提供未经验证的工期承诺。
