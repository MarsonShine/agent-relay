# M2：本地研发闭环

状态：M2.1–M2.6 已实现并通过本地闭环验收，真实试点限定 Windows。需求契约版本：M2-executor-v1（包含 M2-events-v1）、M2-workspaces-v1、M2-handoff-v1、M2-verification-v1、M2-feedback-v1、M2-runtime-v1。

## 原生事件与执行契约

`src/adapters/codex/events.ts` 将单次 CLI 的分块 UTF-8 JSONL 转为通用 started/progress/usage 事件及轮次结果。当前仅接受本次试点已验证的 0.163.0-alpha.10.2；其他版本显式拒绝。分别限制总输出、行长和事件数；重复事件去重，冲突、截断、无终态与非法序列不能证明成功。未知信息事件不能推动完成。

`CodexExecutor` 实现 start/continue/cancel/reconcile。doctor 通过同一启动命令验证实际 CLI 版本；任务正文通过 stdin 传入，原生命令使用参数数组与 shell:false。启动程序及可选 bootstrap 参数只能来自可信控制配置。完整输出 schema 同时传给 CLI 和模型提示，避免模型自行猜测结果格式。

CLI 轮次结束不等于任务完成。只有进程退出、完整成功终态、严格结果 schema、非空结果及匹配的需求/代码版本同时成立，才发出角色 completed。blocked 映射为未接受结果；非零退出、错误终态、缺失/超大/无效成果、旧证据都不能被模型总结覆盖。角色 completed 仍需后续工作流验证才能成为任务 succeeded。

角色配置支持 codex-cli / openai / gpt-6-luna，原生参数仅接受已验证的 low。design/review 必须只读；Run 配置必须等于任务冻结的对应角色配置，不能在交接时扩大权限。实施会话使用 GPT-6 Astra，应用内部真实测试调用使用 GPT-6 Luna。

## 工作区与权限

Codex 请求必须带控制层声明的工作区。写入只允许指向原 checkout 之外的隔离 worktree，且有基线提交；适配器拒绝原路径、其子路径及缺少声明的写入请求。WorkspaceExecutor 从持久登记生成声明，替换调用方提供的路径，执行前核对工作区、当前 Run 所有者及冻结的后端/权限/版本；模型或任务文本不能自行指定该声明。

Windows 显式保留原生 elevated 沙箱。只读角色禁用 sandbox_approval、request_permissions 等能力扩展审批，保留执行规则审查及所有项目规则。环境保留继承的 Codex 策略与本机认证上下文，但不转交 GitHub、其他供应商密钥或 NODE_OPTIONS。Git checkout hooks 与 filters 由工作区预检拒绝。Codex MCP/hooks 与生产控制目录的完整隔离仍须在真实服务调度启用前审计；服务默认注册模拟执行器；显式开发模式关闭扩展与桌面工具桥并拒绝未经审计的项目运行时扩展。

成果目录位于 Agent 工作区之外，每个 Run 独占新目录。最终输出必须是大小受限的普通文件，符号链接和重复目录拒绝。stderr 有界收集并在保存前脱敏；原始输出和本机续接资源仅留在私有运行目录，不进入公开 fixtures。

## 续接与生命周期

不透明续接引用绑定任务、完整角色配置和规范化工作区。新 Run 可以显式续接同一资源；角色、模型、权限或工作区变化必须新建会话。拒绝 --last；实际返回另一个会话时拒绝结果并清空该引用。

启动前取消会锁住启动意图，异步预检完成后也不会再创建进程。运行时限取角色时限与任务剩余期限的较小者；stdout/stderr 合计限额，超限也触发停止。Windows 强制终止拥有的活动 PID 树，Linux 终止进程组；只有终止确认和输出管道关闭后才报告 stopped。父进程已经退出但管道仍被占用时不猜测 PID，返回停止未知。此时控制器必须保留租约。

新适配器实例没有旧进程的可靠身份，reconcile 返回 unknown，绝不根据裸 PID 或过期时间启动第二位写入者。M3 负责跨服务重启的身份和副作用核对。本阶段未承诺软中断或后台/脱离进程恢复；测试工具必须保持前台。

## M2.2 登记与 Git 生命周期（M2-workspaces-v1）

SQLite migration 4 记录原仓库及 common-dir 身份、基线提交、任务分支、规范化路径、需求版本和工作区状态。先持久化 creating 意图，再执行 Git；Git 已成功而数据库未确认时保留未完成意图，拒绝自动重放。inspect 只核对现状，不把未知创建或删除操作自动重试，恢复调度留给 M3。

实现工作区在原 checkout 外创建 codex/task-<task-id>/work 分支，以记录的 SHA 为基线；原 checkout 的未提交源码不复制、不修改。审查使用独立 detached HEAD worktree，记录明确的需求版本和提交，并保存有界内容摘要。Git worktree lock 仅用于防止清理/移动，不是文件写锁。

仓库规则必须能从该提交复现；本地未提交/忽略的 AGENTS、.agents、.codex 配置导致预检失败。自定义 checkout hooks、checkout filters、自定义 fsmonitor 脚本、symlink/submodule 树以及隐藏或稀疏 index 暂不接入，直接拒绝，不通过忽略规则或执行隐含脚本绕过。内容摘要拒绝链接/特殊文件，限制 100000 项、单文件 32 MiB、合计 256 MiB，超限显式失败。

咨询使用干净且匹配记录 SHA 的原仓库只读声明，不创建分支或 linked worktree。清理只允许终态任务、无占用且干净的登记 worktree；忽略文件也会阻止清理，不使用 force/reset，不删除分支，保留已提交历史。咨询和清理同样受当前 Run 占用约束。


## M2.2 Run 占用与结果校验

WorkspaceAccess 在 SQLite 事务中取得任务、工作区和 Run 的唯一占用，绑定所有者令牌与 Run 已保存的需求/代码版本。获取前后核对活动租约、冻结配置、后端版本及任务控制意图；同一 Run 重复启动也会被拒绝。过期、隔离为 unknown 或服务重启都不释放占用。只有控制器证明执行停止后，Runs.finish 或 Runs.confirmStopped 才在结算事务中删除占用。

WorkspaceExecutor 可包装 CodexExecutor 或测试执行器。可写实现使用登记的实现 worktree；review 使用独立只读快照；尚无实现工作区的只读咨询使用原仓库。准备期间的取消锁住启动意图，后续异步准备完成也不得启动进程。新实例不能仅凭数据库记录推断旧进程已停止。

后端完成事件暂存，只有已停止并通过执行后工作区校验才转发；不会补造后端缺失的完成事件。审查校验固定 SHA、需求版本、Git 登记、索引及内容摘要；不匹配时清空成果与续接引用、拒绝完成，并把工作区标记为 tainted。实现允许提交基线的后代；Run 证据仍绑定本次输入版本，后续交接必须明确记录新提交，不能将旧审查套到新代码上。迟到事件和未知停止均不能触发占用释放。

这些约束保护同一控制数据库管理的执行；worktree 和 Git lock 本身不提供操作系统写隔离。只读执行仍依赖已验证的 Codex 沙箱权限。外部进程或用户修改固定快照会使结果被拒收，不会自动 reset、强制清理或重新执行。

M2.2 验收使用临时 Git 仓库、独立 SQLite 连接、假执行器及假 CLI 子进程，无真实模型请求。覆盖脏原仓库保留、基线与固定快照、重复创建、创建后的故障窗口、保守清理、规则预检、独占/过期/确认停止、取消准备竞态、快照篡改、事件迟到、后端身份和 Codex 组合。代码版本与检查结果见 [工作区验收记录](m2/workspace-verification.json)。上述 M2.2 验收本身不覆盖真实闭环、可信验证或项目试点；这些证据由后续切片分别提供。跨服务自动恢复仍属于 M3。

## M2.3 角色交接（M2-handoff-v1）

开发任务按 triage、design、design_review、implement、code_review 或 answer 推进；简单变更必须记录跳过设计的理由。每个阶段使用新 Run，角色与冻结权限分开选择。成果采用严格的阶段 schema，并传递经哈希核对的前序实际内容、需求版本与来源 Run。源文件摘录按固定提交及行号核实，审查必须绑定最新候选并覆盖全部验收项。

实现必须提交基线之后的干净结果，报告的文件集合必须等于 Git 差异且位于 triage 范围内。角色成果及阶段推进在停止结算事务中落库；暂停或取消意图优先，不提交阶段转移。用户答复升级需求版本并重新 triage，不复用旧版本成果。只生成 JSON 或完成事件仍不构成任务验收。

真实服务调度需要显式可信运行时配置；代码交付必须经过下述可信验证和有界审查门禁。

## M2.4 可信验证（M2-verification-v1）

验证命令来自任务创建时冻结的 verification 配置，包含唯一 ID、版本、绝对可执行文件、参数数组、工作区内 cwd、时限和日志上限。模型只得到验证结果，不能指定或删除命令。验证使用共享的有界子进程机制，不经 shell，环境只传递基础运行所需变量，不继承供应商或交付凭据。

实现提交后仍保有同一 Run 占用，控制器运行所有必需检查并保存候选 SHA、需求版本、命令定义哈希、OS/Node 环境、退出码、时间、脱敏日志和日志哈希。只有全部命令成功、停止已确认、候选仍干净且 SHA 未变，才允许进入代码审查。代码审查通过还须重新匹配这份证据。未知停止、超时、日志超限或证据损坏均不能算通过。取消及恢复必须同时核对 Agent 和验证进程；旧进程身份不明时保留占用。

M2 的 deliver 表示本地候选通过验收；不发布 PR，也不表示 M4 的远端交付完成。

## M2.5 有界反馈（M2-feedback-v1）

设计退回、代码修复与可信检查失败共用任务的 maxIterations，不因阶段切换或新 Run 重置。反馈保留发现 ID、触发条件、位置、证据、影响和归属阶段；修复者逐项记录 addressed/disputed 及证据，不能自行宣告解决。后续独立审查必须针对最新候选，逐项给出 resolutions 的复验依据；仍有阻塞项时不能交付。偏好性建议不自动阻塞。

检查失败保留日志及候选 SHA，预算内返回实现；设计缺陷返回设计。预算耗尽时保存当前反馈并 blocked，不再调度模型。重复设计和无实际文件差异的实现不能用新文案或空提交冒充进展。可信 allowedFiles 限定任务可选范围，模型 triage 只能在其中收窄；原始任务文本不能扩大配置授权。

本地交付还核对实现工作树仍为已验证、已审查的干净提交；审查期间发生的外部改动使交付被拒绝。M2.5 的确定性验收包含完整代码审查→修复→新 SHA 复验链路和设计退回/预算耗尽，均不调用模型。

Git 内置文件监控在 Windows Git 2.36+ 作为受支持原生能力保留，`false/no/off/0` 表示关闭；自定义 fsmonitor 脚本仍拒绝，不修改目标仓库配置。依据 [Git 内置监控](https://git-scm.com/docs/git-fsmonitor--daemon)。规则审计按检出文件与可信 allowedFiles 的祖先逐项检查 AGENTS/.agents/.codex，避免扫描与检出无关的全部忽略产物；有效规则的未提交修改和忽略文件仍拒绝。

任务 ref 使用 `codex/task-<task-id>/work`，便于 Windows 将 Git 锁文件写入限定在该任务的 ref 目录。创建 Git worktree 的上限为 120 秒，其他 Git 命令仍为 30 秒。创建结果未确认时继续保留 creating；显式 confirmCreated 只在没有活动/未知 Run、路径/登记/基线/干净状态全部核实后确认现存结果，不重放 Git，不释放未知执行租约。自动恢复调度仍属于 M3。


最新版试点适配器固定为 `0.163.0-alpha.10.2`；此前 `0.162.0-alpha.17.2` 的历史证据不改写。新版 Windows 权限复验分别验证合法读取、控制目录拒读、固定有效补丁拒写及 shell 拒写；使用 GPT-6 Luna，有独立累计额度。运行时目录与凭据目录采用显式 deny，保留 execpolicy 审查并禁止扩权审批；桌面工具桥环境变量不传给子进程。Windows elevated 要求基础 `:root` read；这不授予工作区之外的写权限，也不等同于任意主机秘密的完整隔离。实际原生配置依据 [权限文档](https://learn.chatgpt.com/docs/permissions)。

开发输出使用当前 stage 的原生对象 schema，适配器验证后才编码为通用成果文本；role 不决定成果的 stage。错误阶段、二次编码字符串或不匹配证据被拒绝。真实试点的首轮 triage 暴露了旧联合 schema 的歧义，该失败保留在验收记录中。

## 已停止候选的显式确认

运行结束但未被验收时，保留其未解决项和实际文件状态。实现角色拥有独立的每 Run 临时目录，位于代码工作树之外，通过 TEMP/TMP 和原生权限声明提供；只读角色不因此获得写权限。子代理及桌面工具桥不向内部执行开放。

显式 confirmCandidate 只适用于 blocked/paused、无活动或未知 Run 的任务。操作要求指定当前任务版本和实际提交，核对干净工作树、提交继承关系与可信文件范围，然后记录已观察到的候选及原比较基线。它不启动模型、不接受成果、不释放任何未知租约，也不重置 Run、迭代或截止时间。下一次实现仍必须报告无未解决项并通过可信检查；旧失败成果中的未解决项作为稳定 ID 的待处理声明继续传递，由独立审查给出复验证据。仅在证据全部满足后才清除确认标记并推进。

这条路径处理已确认停止后的已知提交，不提供 M3 的跨服务进程发现或未知副作用自动恢复。
