# 架构设计

## 分层

CLI → 本地服务 → 工作流控制器 → Agent 执行接口 → Codex CLI 适配器。

未来 API Agent 运行时实现相同执行接口，在内部对接官方模型 API、工具执行和上下文管理。工作流不依赖供应商消息格式。模型供应商适配器属于 API 运行时内部，不与顶层执行后端混为一谈。

一个 TypeScript 应用内部划分 cli、service、workflow、agents、adapters、workspace、verification、github、storage 模块；初期不拆微服务或公共插件 SDK。

本地服务为唯一调度者，通过 SQLite 事务、任务版本号和租约避免双重领取。CLI 经本机受认证通道提交请求。M1 使用 127.0.0.1 HTTP 和私有目录内的随机 Bearer 令牌，拒绝浏览器 Origin 并验证 Host；同一数据目录固定监听端口。具体边界见 [M1 契约](m1.md)。禁止默认绑定公网。未来 Web UI 使用相同应用服务。

## 数据与权威来源

| 实体 | 主要内容与约束 |
| --- | --- |
| Task | ID、仓库、来源、需求版本、阶段、运行状态、版本号、总预算；阶段转移使用条件更新 |
| AgentProfile | 角色、执行器、模型、原生参数、权限、超时；执行时冻结配置快照 |
| Run | Task ID、角色、attempt、配置快照、执行器版本、续接引用、结果；每任务最多一个活动写入 Run |
| Event | Run/Task、顺序号、类型、时间、脱敏载荷；本地顺序号唯一 |
| Artifact | 内容地址或路径、类型、哈希、来源 Run、需求版本及提交；不可默默覆盖 |
| Finding | 稳定 ID、证据、严重性、归属阶段、处理状态、复验结果 |
| Validation | 命令定义版本、提交、需求版本、环境摘要、退出码、结果及日志引用 |
| Delivery | 仓库、任务、分支、PR、期望 SHA、操作键、外部结果；按操作键唯一 |
| Inbox / Outbox | 外部事件去重键、待执行意图、发送及核对状态 |
| Decision | 问题、决定、来源、范围和版本；用户答复成为新事件 |

SQLite 保存状态、关系和小型事件；文件保存较大日志和成果，数据库保存引用。原生会话是执行器的续接资源，不是任务真相。第一版使用普通事务和追加事件日志，不要求完整事件溯源框架。

状态迁移、运行领取和追加事件在同一事务落库；M3 将 launch 意图纳入同一事务，并在验证及成果副作用前保存版本化意图。Git 工作树先登记 creating/removing 再执行，恢复仅确认事实。M4 的远端发布意图与状态同事务提交，使用来源版本、需求版本、候选 SHA 和操作键核对，单独保存本地验收与远端反馈生命周期。详见 [M4](m4.md)。磁盘成果先写临时文件再原子发布，引用提交失败产生的孤立文件可后续回收。数据库损坏或成果缺失应显式失败，不根据模型总结补造事实。

## Agent 执行接口

M1 已固化 [版本化实体](../src/core/contracts.ts) 和 [执行接口](../src/core/execution.ts)，通过模拟执行器及替换实现验证。这里定义职责，不承诺所有后端支持所有动作；Codex CLI 生产适配器属于 M2。

- capabilities：声明原生恢复、取消、只读/工作区执行、结构化输出、模型参数和用量可见性。
- start：接收任务输入、角色配置、成果引用、工作区及策略，产生运行句柄与事件流。
- continue：携带不透明的原生续接引用和新的交接材料；不支持原生续接时由控制器显式新建运行。
- cancel：请求停止并返回已停止或未知；未知时不得释放写租约或开始下一位写入者。
- reconcile：在重启后核对已有执行是否仍活动、是否已结束以及工作区结果。
- result：终态、交接成果、验证引用、续接引用、用量与错误类别。

通用事件包括 started、progress、artifact、usage、input_required、completed、failed、cancelled。适配器保留原生错误引用；未知可忽略事件允许记录并继续，但不能据未知事件推断成功。

输入与输出使用带 schemaVersion 的结构。校验 JSON 结构之后，还须验证目标仓库、成果存在性、SHA、权限和允许的状态转移。

角色配置分为通用参数与执行器原生参数。只提供经过验证的映射，不把不同供应商的 high 等选项宣称为相同能力。记录请求值及可验证的实际配置；无法确认时注明未知，不静默换模型。

跨后端转交传递需求、决策、成果、发现和证据，不能直接传递另一个后端的原生会话历史作为可恢复会话。

## Codex CLI 适配器

使用可配置且经 doctor 验证的可执行路径。通过参数数组、shell:false 启动真实可执行程序；任务文本走 stdin，不拼接 shell 命令。

优先使用 exec、--json、--output-schema 和显式会话 ID 续接。不得用 --last 选择任务会话。首次启动与 resume 参数支持不同，具体排列由 M0 验证并版本化。持续任务不使用 ephemeral。

分别处理 stdout JSONL 和 stderr，支持半行、多行、超长输出与截断。退出码、终态事件和成果检查联合决定运行结果，缺少终态的退出标记为需要核对。

每次运行显式声明 cwd、模型与执行政策，复用用户认证但不复制认证文件。受控加载项目规范；检查环境、hooks、MCP 和本地配置是否扩大执行能力。不通过忽略项目规则获得便利。

关闭 stdin、软终止、超时升级、Windows/Linux 子进程树停止与孤儿进程核对在 M0/M3 实测。CLI 没有事件输出不一定是卡死，不能仅凭静默立即重启写入任务。

## 工作区、权限和验证

每任务独立 worktree 与 codex/ 分支，创建前记录基线提交，不改动用户原工作区。审查针对固定提交，只读访问；审查期间禁止写入该快照。

worktree 不是安全沙箱。使用 Codex 已验证的权限控制及必要的操作系统隔离。控制器数据库、GitHub 凭据和交付工具不对工作 Agent 开放；环境变量按需要传递。

项目检查命令来自可信配置，并使用明确 executable/args/cwd。模型可以建议新检查，但不能自行删除或降低验收门禁。检查失败、跳过、无法运行分别记录。

原始工具输出和仓库内容均视为数据，不能授权合并、改变预算或读取凭据。公开日志默认脱敏且限制大小；私有任务内容不得自动上传至工具源码仓库。

## 并发与副作用恢复

任务写租约关联 Run 和进程身份，不能仅用可能被复用的 PID。租约超时先核对进程并隔离未知状态，不能直接重启第二个写入者。

GitHub 操作先落意图，再执行，再记录结果。崩溃窗口通过仓库、head 分支和任务标识查询已有 PR，确认后补记结果；不承诺远端 exactly-once。重试推送和 PR 前核对远端 SHA 与用户修改。

需求变更增加版本；旧验收与设计重新判定有效性。代码变化使旧代码审查失效，验证可以按明确依赖范围复用，不能把旧 SHA 的成功当作当前提交成功。

M3 新运行使用私有单次启动目录和独立守护进程保持 OS 句柄所有权，服务重启通过停止请求/凭证核对；裸 PID 不作为跨进程终止依据。Agent 与可信验证都确认停止才释放占用；未知与旧版未登记执行保持隔离。详见 [M3](m3.md)。
