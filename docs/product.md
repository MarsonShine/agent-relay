# 产品规划

## 定位与用户

Agent Relay 面向需要把多轮 AI 研发协作自动化的个人开发者。第一版为单用户、本地常驻服务加 CLI；支持配置多个目标仓库，但默认仅执行一个任务。首个试点是 MS.Microservice。

用户提供任务及执行政策；系统调查需求、提出必要问题、实施并验证，保留明确的决策与成果。系统只在已授权范围内推进，遇到业务决策缺口、权限或预算限制时进入可恢复的等待状态。

## 已确定范围

- TypeScript，第一版通过命令调用 Codex CLI，不以 SDK 为核心依赖。
- 提供设计、实现和审查三个默认角色；同一模型可承担多个角色，各自使用独立会话。
- 每个角色可选择经当前运行时验证的模型、思考参数、权限与预算；不支持的配置必须报错。
- GitHub 为第一版交付平台；拟定公开源码仓库为 MarsonShine/agent-relay。
- 后续直接模型 API 只采用官方服务。DeepSeek 属于后续 API Agent 路线图，不需要在 M0 接通。
- 第一版完成任务到 PR 的闭环。自动合并属于后续阶段，默认关闭。

## 用户流程

1. 注册本地目标仓库、明确允许的执行范围和项目验证命令。
2. 提交本地文本任务，或在 M4 导入指定 GitHub issue。
3. 系统区分咨询、缺陷修复和功能变更，整理验收标准与未决问题。
4. 信息充分时继续；需要用户决定时保存问题并等待答复。
5. 代码任务在专属 worktree 中实施；独立审查针对固定提交与需求版本。
6. 有效反馈引导局部修复或重新设计，受总预算及轮次限制。
7. 验收通过后，按交付政策推送并创建或更新 PR，处理 CI 与已授权来源的反馈。
8. 展示成果、验证证据、剩余风险及 PR 状态。

咨询任务不必创建工作分支或 PR。简单变更允许省略正式设计文档，但不能省略任务目标、影响范围和必要验证。

## 完成条件

- 回答任务：答案有来源或仓库证据，未决事项已披露。
- 代码任务：满足版本化验收目标；必要检查通过；阻塞审查意见解决；交付记录对应当前提交。
- 计划或代码仅生成不代表任务完成；必要环境缺失时标记未验证。
- v1 的完成是 PR 达到预定交付条件，不表示已合并。

## 默认工程政策（可配置）

- 同时执行一个任务；每个任务仅一个代码写入者。
- 修复最多三轮，设计退回和实现修复均消耗同一任务迭代预算，不能互相重置计数。
- 执行前必须有有限总时限和单次运行时限；默认具体数值由 M0 的实测确定。
- 按后端能力报告用量。金额未知时显示未知；估算必须标识，不能宣称严格美元限额。
- 暂停不继续调度；取消后不再发布；等待答复不占用模型进程。
- GitHub 评论仅在配置的可信参与者与任务范围内触发续跑；机器人自身消息不递归触发。

## 不属于 v1

API Agent 工具循环、动态招募 Agent、通用流程编辑器、多租户、远程 worker、自动合并、模型训练、向量数据库和长期用户记忆。

## 发布前待解决

许可证选择、已验证 Codex/Node 版本、默认超时、GitHub 身份与权限、试点任务和模型预算。上述项不改变已确定的执行后端边界。
