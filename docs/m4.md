# M4 GitHub 交付契约

版本：M4-delivery-v1。GitHub 功能仅由可信配置启用；本地任务保留原有验收语义。`github` 配置冻结仓库名称与数字 ID、目标 base、发布许可、可信反馈者数字 ID/login/范围、非空 requiredChecks（名称及 GitHub App ID）、有限轮询间隔/次数/页数。未知配置被拒绝。

`task import --issue N --key KEY` 在已登记开发仓库中导入指定公开/私有 issue 的当前快照。保存 issue ID、更新时间、内容摘要和原文；同键重试保留原快照，来源和 Task 同事务创建。外部文本只能作为需求，不能配置命令、路径、模型、凭据、预算或交付权限。后续 issue 编辑不自动修改已导入需求。

控制层通过官方 GitHub REST（固定 api.github.com，版本 2026-03-10）访问；凭据由本机 gh 认证读取，不传递给 Agent。原始任务和凭据只保留在私有目录。

本地验收与远端交付独立：`accepted` 仍要求当前需求/提交的完整成果、可信验证、独立审查、未解决发现为空、干净工作树及全部执行占用释放。交付意图绑定来源摘要、需求版本、候选 SHA、base SHA、期望远端 SHA、专属分支及持久 PR marker。意图先于副作用提交；每个步骤只可领取一次，未知结果必须核对，不直接重放。

远端适配器只向固定 GitHub 仓库普通推送，不 force，不 merge。base、远端 head、PR 身份/marker/状态均需匹配。原生 push 使用持久守护进程；核对停止状态后才采信远端结果。PR POST 结果未知时查询包含关闭状态的完整 PR 列表，匹配已有结果；仍未知则阻塞，不重复 POST。分页超过可信页数上限显式失败。PR 自动随分支更新；应用不覆写用户的 PR 标题/正文。

轮询先事务消耗次数并记录下次时间，使用任务原绝对截止时间。每次读取完整有界评论集合，持久 ETag/body 支持条件请求；来源 ID、更新时间和正文摘要共同去重，因此旧评论编辑不会被时间 cursor 隐藏。自己的已登记事件 ID 或当前操作 marker 被抑制；同一登录者的独立评论仍进入收件箱。任何分页不完整都不能提交新 CI/收件箱证据。限流遵循 Retry-After、reset 和 x-poll-interval，普通权限拒绝直接阻塞。

CI 只接受指定 head SHA 上可信 App 的非空冻结检查集合；同 suite 的新 rerun 替换旧结果，不同 suite 全部成功才通过。缺失、pending、未知、重名不可信上下文、传统 status 同名歧义均不通过。检查 failure 与取消/超时等基础设施状态分列。反馈与服务调度接入尚在后续切片实现。
