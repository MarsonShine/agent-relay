# M3：持续协作和可靠恢复

需求契约：M3-20261021-v1。M3.1–M3.5 已实现；以下区分确定性恢复验证、真实实验和未完成的业务验收。真实业务任务仍未 accepted，不能以角色完成或可信检查单独替代独立审查。

## M3.1 需求版本

`task revise ID --version N --requirement-version N --input FILE` 用新正文替换需求，保存本地用户决定并增加需求版本，回到 triage。仅 queued、waiting_user、paused、blocked 且没有活动或未知 Run 时允许；paused 保持暂停。任务版本和需求版本均须匹配。终态不能改写。

answer 必须匹配当前问题 ID/版本，决定保留并传入新 triage。替换需求使旧问题失效；旧成果、阶段交接和可信验证保留作历史，不能验收新版本。决定历史最多 100 条，达到上限拒绝变更。所有变更保留累计 Run、修复次数和绝对截止时间。waiting_user 不领取 Run，暂停等待后恢复仍等待同一问题。

验证：tasks/controller/development 回归覆盖版本竞争、等待零调用、旧成果排除和重开存储后的预算保留。

## M3.2a 持久进程所有权

共享 OwnedProcess 以单次目录、owner 和独占 gate 登记启动，由独立守护进程持有实际子进程句柄。服务退出不转移 PID 所有权；重启通过持久取消请求让原守护进程停止整棵前台进程树，只有其停止凭证才证明已停止。启动前取消通过独占 gate 阻止迟到启动。输出及凭证有界保存在私有运行目录。

守护进程失联、停止未知或凭证损坏时 fail closed，不凭 PID、租约过期或日志总结释放占用。当前仍只支持前台工具；逃逸/脱离进程不属于已验证能力。主机断电、守护进程自身被杀后的自动存活证明尚不支持。Codex、可信验证及工作树变更均使用此机制。

验证：共享进程和既有 Codex 假进程测试共 23 项通过。当前开发沙箱拒绝 taskkill 时新旧停止测试均失败；经过权限审查、允许测试停止自建假进程后全部通过，未改变应用权限策略。

## M3.2b 执行器和可信验证恢复

新领取的 Run 冻结 recoveryVersion=1。Codex 与每条可信验证命令各有 Run/owner 绑定的单次守护目录；WorkspaceExecutor 委托后端核对，不因包装器重建丢失恢复能力。新实例核对会请求停止，尚未启动的命令被持久栅栏禁止迟到执行。控制器仍同时核对 Agent 与验证进程，任一 active/unknown 都保留占用。确认停止后遵守持久 pause/cancel；无控制决定时 blocked，不自动接受未结算结果。

旧 Run 没有新协议标记且不存在实际守护登记时维持 unknown。新服务不会把历史进程当成“未启动”。测试覆盖重建 Codex/Verifier 后停止实际文件写入、工具 PID 退出、取消准备竞态、旧记录保守处理及重复领取拒绝。

## M3.3a 持久重试预算

基础设施重试使用 infrastructureRetriesUsed 与 maxInfrastructureRetries（默认 2，最大 10）；语义/格式修复与业务反馈共用 iterationsUsed/maxIterations。retryAt 为持久绝对时间，退避按 retryBaseMs（默认 1000）指数增长、单次最多 10 秒。领取前同时检查退避、maxRuns 和任务原始 deadlineAt；重启、需求替换、暂停恢复不清零任何计数或延长截止时间。

只有适配器明确分类、已停止的只读失败可自动重试，写入角色仍要求显式核对副作用；未知/未分类错误不自动重试。取消优先于重试结算。预算耗尽或下一次退避超出截止时间时 blocked。验证：runs/tasks/controller 24 项通过，含重开存储、需求替换、分类独立计数、退避和取消竞态。

## M3.3b 失败分类与实际进展

适配器只把操作系统明确的 EAGAIN/EMFILE/ENFILE 启动资源失败归类为基础设施重试；不从任意原生错误文本猜测网络、认证或参数可重试性。JSON/严格 schema 解析失败可使用只读语义修复预算；过期证据、未知停止和权限错误不因此变为成功。

设计进展比较证据、根因、不变量、修复层、步骤与验证计划，排除摘要和自行声明的修复回应，并比较当前需求的全部已结算设计，阻止重复方案循环。实现比较候选 Git tree 与基线及历史候选；提交 SHA/文案变化、空提交、回到早期内容不能证明进展。可信检查与独立发现仍按候选版本落库并参与反馈，不能被模型总结覆盖。

验证：workflow/development/Codex 29 项通过，包含摘要/修复声明改变但设计未改变的阻塞，以及真实 Git 候选修复与可信复验。

## M3.4a 副作用意图

SQLite migration 7 增加 execution_intents。领取 Run、消耗总次数和 launch 意图在同一事务提交；意图失败使领取回滚。每条可信验证在启动前记录 requirementVersion、候选 SHA、策略及命令哈希。观察到结果后、发布成果或推进阶段前记录 result 意图（状态、停止事实和输出摘要），不把结果声明作为完成证明。

意图含 Run/owner、类型、证据版本和 prepared/settled/abandoned 状态；status 提供去除 owner 的查看投影。正常结算与意图状态同事务保存；跨服务停止确认后未结算意图标记 abandoned，保留事实并 blocked/paused/cancelled，不重放模型、验证或结果接受。settled 仅表示 Run 已结算，不表示业务验收成功。历史已落库检查与审查继续要求当前需求/候选及完整成果哈希匹配。

验证：事务注入使 intent INSERT 失败时 Run 与计数不落库；重开存储保留所有权与结果意图，停止后不重放，旧 Run 不能写入新意图。

## M3.4b 工作树副作用恢复

Git create/unlock/remove 同样交给独立守护进程；creating/removing 登记先于副作用。控制器恢复 Run 时也核对未完成的 Git 进程，未证明停止不会释放占用。无活动 Run 后执行启动扫描：创建仅在 Git 登记、路径、基线、需求版本、干净状态全部核实后转 ready；删除仅在路径与登记都已消失后转 removed。

缺失、部分创建、解锁后未删除、脏内容或旧版无停止证明均保留待处理状态，不重放 Git、不 reset、不强删。已确认停止的未完成操作记录 workspace.recovery_pending。扫描只确认现状，不授予验收，也不自动恢复模型调度。

验证：工作区/占用/开发 24 项覆盖均通过（初次仅旧错误文案断言失败，保持文案兼容后针对性 3 项复验通过）。包含真实临时 Git 创建/删除后的注入中断与启动前栅栏。

## 实测发现的租约快照修复

首个真实尝试在模型进程启动前失败，仍计入累计额度。证据：工作树准备期间数据库持续续租，但 WorkspaceExecutor 传给 Codex 的 Run 仍带初始 leaseUntil，导致过期快照被拒绝。不变量是已续租且仍拥有工作区的运行应交接当前租约；所有角色的 start/continue 都受影响。修复在工作区所有权校验后重新读取已保存的 Run，保留 owner、冻结配置和证据校验，不绕过过期/取消检查。短租约慢准备、实际过期占用、准备期间取消 3 项回归通过。

## 需求变更与进展历史的边界

代码 tree 循环检测只比较当前需求的输入版本及已结算候选，不能把工作树的历史初始基线强加给新需求。显式新需求可以要求恢复旧内容，但仍须产生新的干净提交、可信验证和独立审查；同需求 A→B→A 仍 blocked。两个真实临时 Git/可信检查回归分别证明这两条路径，均无模型调用。

## 有界反驳与独立复验

真实审查的换行发现与原始 Git blob/文件字节矛盾：两者都含末尾 LF。流程原先虽允许 disputed 回应，却强制实施产生新 SHA，无法处理不需要改代码的反驳。M3 仅在已有当前候选、所有待处理发现均有 disputed 证据、且至少一个发现首次进入反驳时，允许返回相同 SHA 与空 changedFiles。原先没有候选/发现的零修改实现仍拒绝；新空提交、代码 tree 循环与反复同一反驳仍拒绝。

这条路径始终重跑固定可信检查，后续独立审查必须绑定本次实施记录并逐项给出 resolutions 与验收覆盖，实施者不能自行解决发现或完成任务。反驳/退回共享原修复预算，不增加额度。设计采用相同的新反驳判断。14 项流程/协议回归及零修改初次实施负向检查通过。

进展检测统一使用实施交接的比较基线及历史实施对象的 baseRevision/resultRevision。显式 confirmCandidate 只确认已停止的实际提交，尚未验收，不能把该候选自身当成已完成进展。既有候选恢复测试发现并覆盖了这一回归，原有未解决声明、可信检查和独立审查门禁保留。

守护进程冷启动时间计入单次绝对截止时间。若启动前已耗尽预算，保存明确的 timeout 停止凭证且不启动工具；取消使用单独诊断。短截止时间下的无副作用回归及既有 Codex/所有权测试 26 项通过，未延长预算。
