# 工作流与交接

## 阶段与运行状态分离

阶段：triage → design → design_review → implement → verify → code_review → deliver。

运行状态：queued、running、waiting_user、paused、recovering、blocked、succeeded、failed、cancelled。

阶段表示在做什么；运行状态表示是否推进。咨询可由 triage 转为 answer 并验证后完成。简单变更可跳过 design/design_review，但须保存理由、验收标准和影响范围。

## 状态转移规则

| 当前位置 | 触发与依据 | 后续动作 |
| --- | --- | --- |
| queued | 预算、权限、仓库及执行器预检通过，成功取得租约 | running |
| triage | 需求足够明确且属于授权范围 | 进入设计、简单实现或回答 |
| 任意活动阶段 | 缺少无法由项目规则决定的业务信息 | 保存结构化问题，waiting_user |
| waiting_user | 匹配当前问题版本的用户答复 | 更新决策/需求版本，重新校验后恢复 |
| design_review | 方案满足验收目标且无阻塞缺口 | implement |
| design_review | 设计发现有效缺陷 | 消耗迭代预算，返回 design |
| verify | 检查通过且证据对应当前提交 | code_review |
| verify/code_review | 实现缺陷 | 消耗迭代预算，返回 implement |
| code_review | 设计契约缺陷 | 消耗迭代预算，返回 design |
| code_review | 无未解决阻塞发现且验证充分 | deliver |
| deliver | 外部操作核对成功，PR/CI 满足交付政策 | succeeded |
| 任意活动阶段 | 用户暂停 | 停止新调度，终止/核对活动运行，再进入 paused |
| paused | 用户恢复，状态与工作区核对通过 | queued，保留阶段和已用预算 |
| 任意未终态 | 用户取消 | 停止运行并核对，cancelled；不再发布 |
| 任意活动阶段 | 进程重启或外部操作结果不明 | recovering，核对后再决定 |
| 任意活动阶段 | 缺少权限/环境或预算耗尽 | blocked，保存下一步所需信息 |
| 任意活动阶段 | 无法恢复的内部错误 | failed，保留诊断与成果 |

blocked 的解除必须有外部变化、用户决定或明确的新预算；定时器不能自行重置限制。重试次数包括进程重启前已消耗的次数。取消不能撤销已完成的外部操作，必须展示实际已发生的交付。

## 交接成果

- Triage：任务类型、目标、非目标、需求版本、验收标准、影响范围、待决问题。
- Design：调查证据、选择及理由、接口/数据变化、实施步骤、验证计划；缺陷修复包含根因假设、不变量和正确修复层。
- Implementation：基线与结果 SHA、变更摘要、检查证据、未解决项。
- Review：发现 ID、位置、触发条件、证据、影响、严重性、归属阶段。偏好建议不自动阻塞。
- Answer：结论、来源或仓库证据、适用范围和未验证事项。
- Delivery：分支、PR、远端 SHA、CI 状态和剩余风险。

实现者可用证据反驳发现；记录 disputed，再由审查或专门裁决处理。没有证据时不能把争议改成 resolved。预算内无法解决则交给用户，不无限增加审查者。

## 失败分类与循环边界

基础设施失败（暂时限流、网络抖动）使用有限退避；参数不支持、认证失败不得原样无限重试。输出结构错误可在单独的有限修复额度内纠正，仍计入总预算。业务缺陷消耗任务迭代预算。

初始默认最多三轮反馈修复，任务总时限与单次时限必须有限。触发预算上限后停止下一轮；正在执行的取消仍需核对结果。用量不可见时以运行次数与时间作为可执行边界，并披露费用未知。

记录代码/方案变化、发现集合和检查结果以判断进展；重复结果触发无进展检查。文案改变不视为进展。状态不变时不重复发送通知。

## GitHub 输入

M4 使用可配置的有界轮询与持久 cursor；初始建议一分钟，尊重服务限流。外部事件以来源 ID 和更新版本去重，处理自身评论时不再触发任务。

Issue 或 PR 新评论须经可信参与者和授权范围检查。若改变验收目标，先升级需求版本；不能在旧目标下完成。自动合并另见 roadmap，v1 不执行。
